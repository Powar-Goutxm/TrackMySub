# Architecture

**Analysis Date:** 2026-10-09

## Architectural Pattern

TrackMySub implements a clean, unidirectional **N-Tier Layered Architecture** with strict separation of concerns:

```
[ Client Requests (Web / Mobile / Swagger) ]
                    │
                    ▼ (HTTP / JSON)
        JwtAuthenticationFilter
                    │
                    ▼
            Controller Layer
        (Java Record DTOs + Jakarta Validation)
                    │
                    ▼
             Service Layer
  (Business Logic, Transaction Management, IDOR Checks)
                    │
                    ▼
            Repository Layer
         (Spring Data JPA Repositories)
                    │
                    ▼
          Entity / Database Layer
           (PostgreSQL 16 Tables)
```

## Layers & Components

### 1. Presentation & Controller Layer (`com.trackmysub.controller`)

- Exposes RESTful endpoints mapped under `/api/v1`.
- Controllers include:
  - `AuthController.java`: User registration, authentication, token refresh.
  - `SubscriptionController.java`: Subscription CRUD operations.
  - `DashboardController.java`: Aggregated analytics and category breakdowns.
  - `NotificationController.java`: Alert history, unread counters, read-receipt updates.
  - `CouponController.java`: Curated deals matching subscriptions.
- Request payloads are validated at the API boundary using `@Valid` annotations.

### 2. DTO Contract Layer (`com.trackmysub.dto`)

- Exclusively uses **Java Records** (e.g. `SubscriptionRequest.java`, `DashboardSummaryResponse.java`).
- Benefits:
  - Immutability guarantees.
  - Zero accidental mutation across threads.
  - Prevents Hibernate entity leakage and circular JSON references.

### 3. Service Layer (`com.trackmysub.service`)

- Enforces core business domain logic and security boundaries.
- **IDOR Protection:** `AuthenticatedUserService.java` extracts the currently authenticated principal (`User` entity) from `SecurityContextHolder`. Every subscription query or mutation verifies that `subscription.getUser().getId().equals(currentUser.getId())`.
- Key services:
  - `SubscriptionService.java`: Computes billing cycle dates, next renewal projections, and status transitions.
  - `DashboardService.java`: Calculates monthly burn, annualized projections, and category distribution percentages.
  - `NotificationService.java`: Manages alert records and idempotency checks.
  - `EmailService.java`: Handles asynchronous or degraded SMTP dispatch.

### 4. Persistence Layer (`com.trackmysub.repository` & `com.trackmysub.entity`)

- Uses Spring Data JPA repositories extending `JpaRepository<T, UUID>`.
- Entities (`User`, `Subscription`, `Notification`, `Coupon`) use UUID primary keys generated by PostgreSQL's `uuid-ossp` extension.
- Enums (`BillingCycle`, `SubscriptionCategory`, `SubscriptionStatus`, `NotificationType`, `NotificationChannel`) are persisted as strings (`@Enumerated(EnumType.STRING)`).

### 5. Cross-Cutting Concerns

- **Security:** `SecurityConfig.java` enforces stateless session policies and JWT filter chain placement.
- **Scheduled Tasks:** `AlertScheduler.java` runs daily at 08:00 UTC via `@Scheduled(cron = "${app.alert.cron}")`.
- **Global Error Handling:** `GlobalExceptionHandler.java` intercepts exceptions (`ResourceNotFoundException`, `BadRequestException`, `DuplicateResourceException`, `MethodArgumentNotValidException`) and maps them to RFC 7807 `ProblemDetail` structures.
